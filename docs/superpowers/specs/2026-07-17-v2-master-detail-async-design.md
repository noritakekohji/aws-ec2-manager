# aws-ec2-manager v2.0 — マスター/ディテール UI + 非同期実行基盤 設計

- 日付: 2026-07-17
- ステータス: ユーザー承認済み(ロック機能維持を条件に承認)
- 対象バージョン: v2.0.0

## 背景 / 課題

v1.6 時点の課題(ソース確認 + ユーザーヒアリングで特定):

1. **UI フリーズ**: すべての AWS CLI 呼び出しが UI スレッドで同期実行される
   (`Invoke-AwsCli` が `WaitForExit` でブロック)。SSM 実行時はステータスバーに
   「GUI は完了まで応答しません」と表示する設計になっている。
2. **導線の煩雑さ**: 4 タブ(インスタンス / SG / ロール / ツール実行)それぞれに
   独立したインスタンス ComboBox + 更新ボタンがあり、タブ移動のたびに選び直しが必要。
   タブ間同期コード(`Update-DependentInstanceCombos` ほか)が約 500 行に肥大化。
3. **App.ps1 が 3,237 行のモノリス**で見通しが悪い。

## 決定事項

### 1. 画面レイアウト: toolbar + list + detail(マスター/ディテール)

```
┌─────────────────────────────────────────────────────────────┐
│ ヘッダー: [プロファイル▼] [SSOログイン][トークン確認] [設定][ログ]  │
├───────────────────┬─────────────────────────────────────────┤
│ インスタンス一覧(35%) │ 選択中: web-server-01 (i-0abc...)  ●running │
│ 🔍 フィルタ          │ ┌─[詳細]─[SG]─[ロール]─[ツール実行]────────┐ │
│ Name / State / SSM │ │  選択中インスタンスへの操作画面            │ │
│ [更新][起動][停止]    │ │  (タブごとのインスタンス選択は全廃)       │ │
│ [再起動][ロック][解除] │ └───────────────────────────────────────┘ │
├───────────────────┴─────────────────────────────────────────┤
│ ステータスバー: 実行中 describe-instances... [キャンセル] ▓▓░░    │
└─────────────────────────────────────────────────────────────┘
```

- 左ペイン(幅 35% 目安、GridSplitter で可変):
  - フィルタ TextBox 1 つで Name / InstanceId / PrivateIp / PublicIp を部分一致絞り込み
  - 一覧 DataGrid は要点列のみ(Name / ロック / State / SSM / InstanceId)。
    詳細情報は右ペインの「詳細」タブへ移す
  - 電源操作(起動 / 停止 / 再起動)と ロック / ロック解除 ボタンを集約
- 右ペイン: タブ = 詳細 / セキュリティグループ / インスタンスロール / ツール実行。
  すべて左ペインの選択インスタンスに追従。**タブ内のインスタンス ComboBox・
  更新ボタン・タブ間同期コードは削除**
- 右ペイン上部に選択中インスタンスの見出し(Name + InstanceId + State バッジ)を常時表示
- SG / ロールの取得はタブがアクティブになったとき、または選択が変わったときに
  遅延実行し、インスタンス ID 単位でキャッシュ。手動「再取得」ボタンをタブ内に 1 つ置く
- 配色: 現行ダークパレット(slate + sky)を維持。tool-designer の採用実績表に登録する

### 2. ロック機能(維持・ユーザー要件)

- 現行仕様を完全維持する:
  - ロック状態は AppSettings(settings.json)に永続化
  - 一覧に「ロック」列、表示ラベルに [ロック] バッジ
  - ロック中インスタンスへの 起動 / 停止 / 再起動 / SG 適用 / ロール適用 / SSM 実行 をブロック
    (メッセージボックス + ステータスバー + WARN ログ)
- ロック / ロック解除ボタンは左ペインに配置

### 3. 非同期実行基盤(AsyncRunner)— イベント駆動、常時ポーリングなし

- **バックグラウンド Runspace + イベント駆動の完了通知**。UI 側の DispatcherTimer による
  常時ポーリングは行わない(ユーザー要件)。アイドル時のバックグラウンド動作はゼロ
- 完了通知: 背景 Runspace が Work 完了時に自ら `$window.Dispatcher.BeginInvoke($callbackDelegate, $result)`
  を呼んで UI スレッドへ push する
  - OnSuccess / OnError / OnProgress の scriptblock は UI Runspace 側で delegate に変換してから
    背景 Runspace へ渡す(Add_Click ハンドラと同じ実行機構で UI スレッド上で動く)
  - この方式が実機で不安定な場合のフォールバックは「タスク実行中のみ起動し完了で停止する
    DispatcherTimer」とする(それでも常時ポーリングはしない)
- すべての AWS CLI 呼び出し(describe / start / stop / SG / ロール / SSM)がここを通る
- API 形:`Start-AsyncTask -Name <表示名> -Work {scriptblock} -OnSuccess {} -OnError {} [-OnProgress {}]`
  - Work は背景 Runspace 内で AwsManager.psm1 を import して実行
- データの自動定期更新も行わない。取得はユーザー操作(更新ボタン / タブ表示 / 選択変更)時のみ
- 同時実行は 1 つ(直列)。実行中:
  - 操作系ボタンは無効化(現行 Set-UiBusy 相当)
  - 一覧スクロール・フィルタ・タブ切替・詳細閲覧は可能
  - ステータスバーに実行中タスク名 + プログレスバー + **キャンセルボタン**
    (背景 Runspace と子 aws プロセスを kill。SSM 実行中なら現行同様 cancel-command も送る)
- SSM の途中経過は OnProgress 経由でステータスバー / 出力欄に反映
  (SSM API 自体は push 通知を持たないため、背景 Runspace 内での間隔付き状態確認は継続する。
  UI 側にタイマーは置かない)
- `$pumpUi`(DoEvents 相当)と再入抑止のための全ボタン無効化ロジックは廃止し、
  AsyncRunner の直列実行で置き換える

### 4. コード構造

```
App.ps1                # エントリ(~150 行): モジュール import、XAML ロード、src/*.ps1 の dot-source
MainWindow.xaml        # 新レイアウト
src/
  AsyncRunner.ps1      # 非同期実行基盤
  AppState.ps1         # 選択状態・インスタンスキャッシュ・SG/ロールキャッシュの一元管理
  UiCommon.ps1         # Find-Control、ステータスバー、確認ダイアログ等の共通 UI ヘルパ
  InstanceListPane.ps1 # 左ペイン(一覧・フィルタ・電源操作・ロック)
  DetailTab.ps1        # 詳細タブ(現行の詳細ウィンドウ内容をタブ化)
  SgTab.ps1            # SG タブ(差分プレビュー / HTML レポートは現行機能を移植)
  RoleTab.ps1          # ロールタブ
  SsmTab.ps1           # ツール実行タブ(YAML 一覧 / 編集 / SSM 実行)
```

- src/*.ps1 は **dot-source**(WPF イベントハンドラがウィンドウ状態を共有するため。
  psm1 のスコープ分離はここでは不利)
- AwsManager.psm1 / AwsConfig.psm1 / AppSettings.psm1 / Logger.psm1 は現行のまま活用
  (AwsManager は背景 Runspace からも import される)
- 規約維持: PS 5.1 互換(`??` / `?:` / `?.` 禁止)、.ps1 は UTF-8 BOM 付き
- 既存機能はすべて移植する(SG 差分プレビュー / 実効ルール diff / HTML レポート、
  ロール差分、YAML 追加・改名・保存、詳細表示、設定ダイアログ、SSO ログイン、トークン確認)

### 5. 状態設計(empty / loading / error / success)

| 画面 | empty | loading | error | success |
|---|---|---|---|---|
| 一覧 | 「このプロファイルにインスタンスがありません」+ 更新案内 | ペイン内プログレス | ステータスバー + 一覧上部に赤字 | 一覧表示 + 件数 |
| 右ペイン共通 | 「左の一覧からインスタンスを選択してください」 | タブ内プログレス | タブ内赤字 + ステータスバー | 各タブ表示 |
| SSM 出力 | 「YAML を選択して実行してください」 | 進捗テキスト + プログレスバー + キャンセル | STDERR 併記の赤字 | 出力 or HTML をブラウザで開く |
